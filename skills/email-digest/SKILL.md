# Email digest

Build one working digest with the user, then make it repeatable.

## 1. Shape the digest

Ask only what changes the result:

- Which mailbox or mail source should it cover?
- Daily, weekly, or on demand?
- What should always be surfaced: named people, projects, deadlines, requests, or decisions?
- Where should the digest appear?

Use sensible defaults for everything else instead of designing a generic mail system.

## 2. Connect the available mail access

Find the email tool, connector, CLI, or app already available in the workspace. If none exists, help the user choose and connect one that fits their setup. Keep provider-specific setup in the workspace, not in this reusable skill.

## 3. Run a real sample

Read a recent, representative window and produce a concise digest. Group related messages, lead with what needs attention, link or identify the source messages, and separate actions from information.

Show the result and ask what was missing, noisy, or wrongly prioritized. Adjust the digest from that feedback rather than inventing a large policy up front.

## 4. Make it repeatable

Once the sample is useful, turn the exact working procedure into a Superboard action or the workspace's existing automation format. Store the user's stable preferences beside the local workflow so later runs can improve without changing this shared skill.
